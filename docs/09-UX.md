# 09 — UX

## 1. Propósito

Definir la **experiencia a nivel de flujos, estaciones de trabajo, navegación y responsabilidades**.

**No se diseña la interfaz visual** (sin wireframes pixel-perfect, sin sistema gráfico completo, sin inventar pantallas fuera del MVP).

---

## 2. Principio UX central

> El usuario trabaja en **estaciones**, no administra **tablas**.

Las entidades (Concept, Representation, Asset…) aparecen **dentro** de las estaciones cuando el trabajo lo requiere, nunca como IA de navegación principal.

---

## 3. Las seis estaciones

| Estación | Pregunta del usuario | Resultado esperado |
|----------|----------------------|--------------------|
| **Factory** | “¿Qué necesito crear ahora y qué ya tengo?” | Batch resuelto: FOUND / GENERATE → cola Review |
| **Review** | “¿Qué merece entrar a la biblioteca?” | Assets aprobados o descartados |
| **Library** | “¿Qué recurso aprobado uso?” | Encontrar y exportar |
| **Coverage** | “¿Dónde está rota o floja la cobertura?” | Issues accionables |
| **Plans** | “¿Qué vamos a crecer a propósito?” | Plan aprobado listo para Automatic Factory |
| **Settings** | “¿Cómo está configurado el entorno local?” | Paths/providers/umbrales correctos |

---

## 4. Navegación

### 4.1 Navegación primaria (siempre visible)

1. Factory  
2. Review  
3. Library  
4. Coverage  
5. Plans  
6. Settings  

**Badges útiles (no son flujos nuevos):**

| Badge | Dónde | Significado |
|-------|-------|-------------|
| Review count | Review | items `waiting_review` |
| Failed jobs | Factory o Settings | jobs `failed` recientes |
| Draft plans | Plans | planes draft |

### 4.2 Navegación secundaria

Anidada **por estación**:

| Estación | Secundaria |
|----------|------------|
| Factory | Manual · Automatic · Batches recientes |
| Review | Cola · (filtros) |
| Library | Buscar · Detalle · Exportaciones recientes |
| Coverage | Summary · Issues |
| Plans | Lista · Detalle de plan · Items |
| Settings | General · Providers · Coverage targets · Jobs |

### 4.3 Deep links lógicos (entre estaciones)

| Desde | Hacia | Motivo |
|-------|-------|--------|
| Coverage issue under-covered | Plans (crear item) | acción de crecimiento |
| Coverage review_backlog | Review | limpiar cola |
| Factory batch done | Review | curar generados |
| Plans approved | Factory Automatic | ejecutar |
| Library export | (externo) | consumo |
| Job failed generate | Factory batch detail / Settings providers | diagnóstico |

Estos enlaces son **CTA de flujo**, no menús de entidades.

---

## 5. Responsabilidades de cada estación (UX)

### 5.1 Factory

**Manual**

- Entrada de lista estructurada (pegar/importar/editar filas).  
- Validación visible de campos requeridos.  
- Acción **Preview**: muestra FOUND vs GENERATE sin gastar provider.  
- Acción **Submit generate**: solo faltantes.  
- Resumen final no ambiguo.

**Automatic**

- Selector de **solo planes approved**.  
- Preview de items a materializar.  
- Confirmación de ejecución.  
- Progreso de jobs.  
- Copy explícito: “No genera aleatorio; ejecuta el plan”.

**Estados vacíos**

- Sin providers configurados → CTA a Settings.  
- Sin planes approved (en Automatic) → CTA a Plans.  
- Sin conceptos (early) → mensaje de bootstrap, no CRUD gigante.

### 5.2 Review

- Cola orientada a decisión rápida.  
- Detalle con preview + metadata + prompt + concepto/representación.  
- Acciones primarias: Approve / Reject.  
- Acciones secundarias: Edit metadata / Regenerate / Mark duplicate.  
- Tras Approve, el item desaparece de la cola (feedback claro).  
- Nunca presentar Review como “Library con botones”.

### 5.3 Library

- Búsqueda y filtros (concepto, representación, theme, orientación, estilo, provider).  
- Detalle de asset **approved only**.  
- Exportar información (manifest / selección).  
- Sin botones Generate/Approve.  
- Si el usuario busca algo inexistente: empty state con enlace opcional a Coverage/Plans (no a generación directa obligatoria).

### 5.4 Coverage

- Arriba: números clave (concepts, under-covered, over-covered, waiting review).  
- Abajo/listado: **issues** con severidad, descripción, CTA.  
- Gráficos solo si acompañan un issue o un count accionable.  
- El usuario debe poder responder en < 1 minuto: “¿qué está mal y qué hago?”.

### 5.5 Plans

- Lista de planes por estado (draft / approved / archived).  
- Editor de items (action, concept, representation, targets, constraints).  
- Approve con confirmación (“habilita Automatic Factory”).  
- Progreso de items (pending / scheduled / fulfilled) **post-ejecución y review**.  
- No botón “Generar ahora” que salte a provider sin pasar por Factory (el CTA correcto es “Abrir en Automatic Factory”).

### 5.6 Settings

- Media root y validación.  
- Providers (enable, default, secrets masked).  
- Targets default de coverage.  
- Matching policy (exact style, etc.).  
- Concurrency / retries de jobs.  
- Sin tablas de producción.

---

## 6. Modelo mental del usuario (onboarding conceptual)

Orden didáctico (puede ser checklist de primer uso, no un 7º flujo):

1. Configura Settings (paths, provider stub/real).  
2. (Opcional) Crea Theme y Plan draft → approve.  
3. O carga Manual Factory needs.  
4. Genera → ve a Review.  
5. Approve → Library.  
6. Mira Coverage → ajusta Plans.

El producto no fuerza un wizard largo; sí debe hacer obvia la cadena.

---

## 7. Lenguaje de UI (microcopy)

Usar el lenguaje ubicuo del dominio:

| Preferir | Evitar |
|----------|--------|
| Waiting Review | “Pending images” ambiguo |
| FOUND / GENERATE | “Skip / Create” confuso |
| Approve to Library | “Publish online” |
| Coverage issue | “Analytics insight” vacío |
| Plan approved | “Plan running” (el plan no corre; Factory ejecuta) |
| Concept / Representation | “Tag / Folder” como modelo principal |

---

## 8. Densidad y ritmo de trabajo

| Estación | Ritmo |
|----------|-------|
| Review | Rápido, teclado-friendly, decisiones en serie |
| Manual Factory | Metódico, validación, preview antes de costo |
| Automatic Factory | Supervisión de corrida |
| Library | Exploratorio / búsqueda |
| Coverage | Diagnóstico |
| Plans | Diseño deliberado |
| Settings | Infrecuente, cuidadoso |

---

## 9. Feedback y confianza

1. **Nunca** mostrar un asset generado como “ya en Library”.  
2. Tras generación: toast/banner “N enviados a Review”.  
3. Tras approve: “En Library”.  
4. Jobs: estado visible (queued/running/failed).  
5. Errores de provider: accionables (credencial, red, cancel).  
6. FOUND: mostrar **qué** asset se reutilizó (confianza de matching).

---

## 10. Accesibilidad (requisitos UX)

- Contraste suficiente en estados (approve/reject).  
- Focus visible.  
- No depender solo del color para FOUND vs GENERATE.  
- Targets de click adecuados en acciones de Review.  
- Previews con texto alternativo = concept + representation.

---

## 11. Out of scope UX (MVP)

- Colaboración multi-usuario en vivo  
- Comentarios tipo Figma  
- Light table avanzada de mil assets  
- Theme builder visual complejo  
- Onboarding marketing animado  
- Dark/light perfectionism como bloqueante  
- Pantallas de “Conceptos” / “Assets” admin  

---

## 12. Criterios de aceptación UX (producto)

1. Un usuario nuevo identifica las 6 estaciones en la nav sin documentación externa.  
2. No existe ítem de menú primario llamado Conceptos/Representaciones/Assets.  
3. El camino Manual → Review → Library se entiende sin training largo.  
4. Automatic Factory no ofrece planes no approved.  
5. Coverage muestra al menos un issue accionable cuando hay under-coverage en fixtures.  
6. Library no expone acciones de Review/Factory.

---

## 13. Relación con diseño visual futuro

Cuando se diseñe UI visual (post-aprobación de fundación y en fase dedicada):

- Partir de estas estaciones.  
- No añadir rutas.  
- Componentes reutilizables en `shared/ui`.  
- Review y Library pueden compartir visor de asset, **no** la misma página.
